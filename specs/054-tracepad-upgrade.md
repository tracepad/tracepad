# Spec 054 — `tracepad upgrade`: an upgrade with a backup and a way back, in the binary

**Status:** ✅ SHIPPED
**Sprint:** October 2026

> An upgrade is where a person has the most to lose: the data the server holds.
> Spec 053 made setup one line to a coding agent, and a first attempt made
> upgrading one line too, as a procedure of shell blocks in the skill. Three
> rounds of review found ten defects each, most of them in the surface the
> previous round's fixes had added: a state file run as code, a PID taken on
> faith, a way back that deleted what it was meant to keep, a secret on a
> command line, a container recreated without its read-only mount. Shell in
> Markdown cannot be tested the way the stakes require. This spec moves the
> procedure into the binary, as `tracepad upgrade`: it plans, backs up, swaps,
> checks, and goes back when the new version does not answer, deleting nothing
> on the way. The agent runs the command and reads its report; the skill says
> four sentences instead of two hundred lines.

---

## Overview

One PR. Deliverables:

- **The command** (Decisions 1–14): `tracepad upgrade --plan`, `tracepad
  upgrade [--to X]`, `tracepad upgrade --check RUN` and `tracepad upgrade
  --back RUN`, with `--json`, in a new package `internal/upgrade`, wired in
  `cmd/tracepad`.
- **The install script** (Decision 15): after it replaces a binary, it asks the
  new binary's `upgrade --plan` what still runs the old one, instead of
  searching for it in shell; its copy of `internal/termsafe` in `awk` is gone.
- **The agent's side** (Decision 16): `docs/agent-upgrade.md` (new) and the
  skill's `references/upgrade.md` (new, short), with a drift test that holds
  every command they name to the binary.
- **Docs** (Decision 17): `docs/cli.md`, `docs/install.md#upgrading`,
  `docs/docker.md`, the quickstart and the README, with what a backup is in
  privacy terms.

Builds on spec 001 (the start's first line, #25; one server per data
directory and the PID its lock records, #20), spec 020 (the image), spec 037
(the skill and `skills install`), spec 044 (erasure, which a backup outlives)
and spec 053 (the install script and the two lines). It replaces the shell
procedure of the closed PR #222, whose spec Decisions (053 #21–#23 there,
never merged) are this spec's input: what they decided about ownership, the
backup, the check and the way back is carried here, and every finding of the
three reviews is answered in Decision 18.

| 9 | **2026-10-05** — **The check, and its verdicts.** The command asks the server itself, at the address recorded in the state — the process's effective `--listen` (flag, `TRACEPAD_LISTEN`, or the default), or the container's published loopback port — over HTTP from Go, with no proxy, never at `TRACEPAD_URL` or `.env`'s address (the CLI on the `PATH` may be the binary that failed, and `.env` may name another server). | 11 | **2026-10-05** — **The way back sets aside; it deletes nothing.** One code path, taken by the upgrade on *not healthy* or on a failure after the stop, and by `--back`; it reads which steps the run completed and undoes those, in reverse. ## Application contract

- `cmd/tracepad`: `upgrade` is a word of the binary's own (beside `serve`,
  `mcp`, `skills`, `version`), dispatched to `internal/upgrade`; `help` lists
  it. `canonicalVersion` moves to `internal/upgrade` (`IsRelease`), where the
  order between versions lives too.
- `internal/upgrade`: `Run(ctx, Options) int`. Its dependencies on the machine
  are interfaces with a real and a fake implementation: processes (list, read,
  signal, start), Docker (the CLI), HTTP, downloads, the clock.
- Run directory: `~/tracepad-backups/<id>/` holding `state.json`, `server.json`
  (process) or `container.json`, `image.json` and `env` (container),
  `data.tar.gz`, `tracepad-<from>`, `tracepad-<to>`, `upgrader`, `count.json`.
- `scripts/install.sh`: Decision 15. `scripts/install-test.sh`: its stand-in
  binary answers `upgrade --plan` from the environment of the case.
- `agent/skills/tracepad/references/upgrade.md` (new), `SKILL.md` (routing
  line and trigger), `agent/skills/drift_test.go` (the commands).

## Edge cases

- **The binary was updated by the install script and the server never
  restarted**: the installed binary answers `to`, the server `from`; the copy of
  `from` is downloaded (Decision 7), and the server is restarted onto the
  installed binary.
- **A binary older than this command**: `docs/agent-upgrade.md`'s bridge
  (Decision 16).
- **Two servers of the command's on one binary**: one run upgrades the binary
  and one server; the plan names the other, still on the old version, and the
  next run (`--data-dir`) restarts it. A way back of the first run puts the old
  binary back, and the report names the other server, which keeps running the
  version it started with.
- **The data directory is a mount point or a symbolic link**: the symbolic link
  is resolved, and the way back works next to the real directory. A mount
  point cannot be renamed, so the server is the person's (the way back could
  not set it aside).
- **No key**: no counts; the verdict rests on `/health`, and the report says
  the counts were not compared and why.
- **A server that answers on its address, but is not the restarted process**
  (another server took the port while it was down): `/health` answers, the
  process has exited, so it is *not healthy* and the way back runs; the report
  names what answers there.
- **The run directory's file system has no room**: refused before the stop
  (Decision 7).
- **The backups root is on another file system than the data**: nothing
  depends on it; the archive is a file, and the restore goes beside the data.

## Out of scope

- Upgrading what is the person's: a service unit, a Compose project, a
  server open beyond this machine, a container outside Decision 4. The plan
  gives them the commands; doing it would need a decision only they can make.
- Deleting backups or anything set aside, or a schedule that does.
- Going back by more than one run, or to a version whose backup is gone.
- Windows. The archives exist; the process discovery does not.
- Downgrades of any kind.
